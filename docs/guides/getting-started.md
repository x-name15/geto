# Getting Started

Welcome to **`geto`**!

`geto` is a resource consumption and entity lifecycle gateway for Node.js and TypeScript. It allows your applications to consume heterogeneous resources (buffers, objects, streams, child processes, web URLs) without requiring the orchestrating layer to know anything about the underlying resource types.

---

## Installation

Install via npm:

```bash
npm install @mrjacket/geto
```

**Requirements:**
- Node.js `>= 22.12.0`
- ESM or CommonJS runtime

---

## The Mental Model in 3 Minutes

In standard software design, developers often create fragmented managers:
- A stream cache to buffer incoming network chunks.
- A database repository to store serializable entities.
- A process manager to track child processes and kill them on shutdown.

`geto` unifies all of this under a single architectural gateway:

```
    Developer gives Resource (T)
                 │
                 ▼
┌─────────────────────────────────┐
│     Adapter (Domain Layer)      │  <-- You define what "consume" means
│   consume(T) -> Representation R│
└────────────────┬────────────────┘
                 │
                 ▼
┌─────────────────────────────────┐
│     Gateway (Core Engine)       │  <-- Assigns UUID, tracks state, freezes entity
│  coordinates lifecycle & store  │
└────────────────┬────────────────┘
                 │
                 ▼
┌─────────────────────────────────┐
│    Storage (Persistence Layer)  │  <-- Memory, Disk, Redis, etc.
│         save(id, R)             │
└─────────────────────────────────┘
```

The gateway **does not care** what the resource is. It only manages identity, state transitions, storage persistence, and retrieval.

## 5-Minute Quickstart

Here is a minimal, complete example consuming and restoring data:

```typescript
import { GetoGateway, MemoryStorage, BufferAdapter } from '@mrjacket/geto';

// 1. Initialize the gateway with in-memory storage
const gateway = new GetoGateway({
  storage: new MemoryStorage()
});

// 2. Select an adapter
const adapter = new BufferAdapter();

// 3. Consume a resource
const original = Buffer.from('Domain Expansion');
const entity = await gateway.consume(original, adapter, {
  metadata: { origin: 'jujutsu-engine' }
});

console.log('Entity ID:', entity.id);         // e.g. "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d"
console.log('State:', entity.state);          // "stored"
console.log('Adapter:', entity.adapterId);    // "buffer"

// 4. Restore the resource at any later time
const restored = await gateway.restore(entity, adapter);
console.log(restored.toString());            // "Domain Expansion"
```

## Basic Lifecycle Transitions

Every entity generated by `consume()` follows a strict, predictable lifecycle:

```
          consume()
              │
              ▼
           STORED  <─────── restore() [Repeatable, non-destructive]
              │
      ┌───────┴───────┐
      │               │
  release()        delete()
      │               │
      ▼               ▼
   RELEASED        DELETED
      │          [Terminal: all further ops throw]
   delete()
      │
      ▼
   DELETED
```

- **`STORED`:** The resource was transformed and its representation safely persisted in storage.
- **`RELEASED`:** The adapter executed its cleanup logic on the resource (e.g. closing a file or killing a process). The representation remains available in storage.
- **`DELETED`:** The entity is permanently deleted from storage. Any further access throws `EntityStateError`.
